## 目标与边界

陌生 Vault 先扫描并在 Vault 内初始化单一配置，再由用户显式选择文章。配置内的 publication.entries、site 和 theme 驱动独立 CLI 生成公开内容包及完整站点项目。用户无需修改笔记属性或把文章复制进工具源码，Obsidian 关闭时也可执行；插件后续复用 CLI。构建与部署分离。

先做纵向可验证的最小流程，再加入部署、评论和编辑器体验。不实现通用任务图引擎、任意 shell 任务、持久化构建计划、增量缓存或移动构建服务。邮件订阅单独规划。

## 第一阶段：陌生 Vault 的发现、初始化与选择（已交付 Windows 首版）

**交付范围**：将已约定的配置、发布清单和诊断实现为运行时校验器；核心负责扫描与选择逻辑；CLI 实现 `inspect`、`init`、`content list/add/remove` 和配置/路径/清单层面的 `check`。源笔记不修改，只有 init 与 content 选择操作写指定配置并保留其它区块。此阶段 check 明确列出引用检查尚未完成，plan 尚不可用。

**实现顺序**：

1. 核对届时依赖兼容性，固定 Node 和 pnpm，建立必要的包清单、锁文件、TypeScript 及测试入口。仅安装这条链路需要的依赖。
2. 按 publication.md 实现版本化统一配置（含清单、site、theme）校验，明确配置路径、源相对路径和调用路径的基准；未知字段及非法版本报错。
3. 实现 inspect：列出源文件、资源和属性线索，不执行插件、不输出正文、不自动选择；跳过系统目录，报告不可读或未检查内容。
4. 实现 init：在指定位置创建单配置及内联空清单，初始附件授权为空，输出显式指定且在 Vault 外，不覆盖已有配置。
5. 实现 content list/add/remove：ID 生成并存入配置内清单；重复操作幂等，停用保留身份，按状态机分层校验，合作写入串行化并检测冲突；覆盖源文件已删除仍可停用和提交后响应丢失。
6. 实现 check 的配置、路径、选择部分及 CLI 结构化输出和退出码，按结果协议验证 data 的封装、passed/failed/unperformed 分区、effect 和 configVersion。添加真实测试与操作说明。

**验收**：陌生 Vault 可扫描和初始化，默认零选择；源文件标记 publish true 也不会自动加入。显式加入无属性文章后只修改指定配置的 publication.entries，保留个人资料、友链及主题设置；停用与恢复保持 ID/slug。跨工作目录、中文空格路径、空清单、重复 ID/slug、越界和写入冲突均有明确结果；只读命令下全部输入哈希不变；init/content 下正文和资源哈希不变。把人工样例复制到独立临时目录验证，不能只在仓库固定位置运行。

**不包含**：Astro 安装、文章转换、部署、评论、插件。通过这一阶段后再进入内容执行。

## 第二阶段：可解释构建计划与公开内容包

**依赖**：第一阶段。涉及 `packages/content-contract`、`packages/publisher`、`tools/cli` 与人工笔记样例。

- 冻结输出内容包 manifest 第一版，与输入配置分开。身份直接来自已验证的配置内清单及 site.pages，不读取源文件名推导 ID，不写回源笔记。
- 先补全 check 的引用检查，再实现只读 plan：解释文章、页面、资料、友链和资源的来源及阻断引用，空集合 buildable false，首版 changes 固定 null 并明确 BASELINE_NOT_SUPPORTED。检查与执行复用同一规则，不让插件维护文件依赖。
- 首批支持标准 Markdown、Obsidian 双链/别名与图片引用；标题链接、Callout、公式按样例加入。块引用、整篇嵌入和插件生成视图先明确诊断，避免承诺完整 Obsidian 兼容。
- 定义输出文件所有权和失败处理：首次拒绝覆盖不属于工具的既有文件；后续仅清理上次 manifest 记录的旧产物。校验失败不破坏上次有效产物。校验与转换消费同一份捕获字节；先暂存再提交，补充进程中断恢复及路径替换验证，不能仅凭原子 rename 宣称事务保证。
- 增加真实内容测试与检查命令，更新 runbook。

**验收**：按 publication.md 的依赖矩阵覆盖已选链接、未选链接/嵌入、无引用附件及 Markdown 冒充图片。plan 能解释每个包含项，不输出未公开正文；完全没有内容时拒绝构建，不覆盖旧产物；零文章但有启用页面、资料或友链时正常规划。配置本身不公开，统一检查页面与文章 ID/路由冲突。相同输入产生相同内容包；改名更新清单 source 并保留 ID；部分撤回及无引用旧附件从新产物移除；输出无本地绝对路径，失败不修改源或破坏旧结果。第二阶段先通过库入口验证内容生成，完整 build CLI 在第三阶段交付。

## 第三阶段：内置默认主题与纯生成站点

**依赖**：第二阶段。涉及 `apps/web` 和 CLI 的构建适配。

- 默认渲染器消费公开内容包，生成首页、文章页、关于页、个人资料、友链、基础导航和 Pagefind 搜索。
- 生成 Astro 项目和静态网站到独立输出，用户不维护站点源码；不得写回工具源码或 Vault。站点 URL / base 字段在此阶段细化并同步输入协议。
- 提供内置 default 主题，落实 colorMode、accentColor 设置；首版不接入外部 CSS、布局覆盖或第三方主题。
- CLI `build` 编排内容执行和网站构建。内容检查、类型检查、测试和构建入口真实可用后接 CI。

**验收**：用 Vault 内单配置构建到独立输出；配置配色影响页面且输入和工具源码不变；丢弃输出后可凭相同输入与固定工具版本重建；首页、文章、关于页、头像、友链、附件、搜索在桌面及移动宽度可用；根路径与项目子路径正确；无 Obsidian、无云密钥也能构建。CI 使用人工样例，不接触私人 Vault。

## 第四阶段：部署适配与状态跟踪

**依赖**：第三阶段；接入前需要用户的 GitHub 仓库、Pages 基路径或域名。

- 选择本地与 CI 的产物交接方式，使用可移植配置和获准公开的快照；不把整个 Vault 上传到 GitHub。
- `deploy` 接受明确构建产物或构建版本，记录上传、构建（若有）、发布结果；`status` 返回同一版本的状态。
- 确定产物保存、撤回与重试规则，防止旧构建覆盖较新的发布；凭据留在管理环境。

**验收**：在授权预览目标中完成一次发布；模拟失败可定位阶段；上传完成不误报部署成功；重试不产生内容重复；本地 `build` 始终无远端副作用。

## 第五阶段：匿名评论与管理命令

**依赖**：稳定文章 ID 和最小网站；接入云端前需要 Cloudflare 目标环境。

- 建立 Worker/D1、本地迁移和公开/管理数据协议；访客填写资料直接提交，服务端固定待审。
- 提供列出、批准、拒绝和导出命令，可由 agent 操作。授权机制与审计在此实现，不要求先做管理网页。
- 实现输入校验、提交频率限制、公开字段隔离和必要的反垃圾措施。

**验收**：匿名不能审核，待审内容不可公开，邮箱不泄露；获批后显示且与文章改名无关；迁移、导出和恢复在测试环境跑通。MCP/CLI 限定环境和操作范围。

## 第六阶段：Obsidian 桌面入口及后续订阅

**依赖**：CLI 构建、部署和状态接口稳定。插件可与评论阶段独立推进，不等待评论实现。

- 插件收集配置、展示诊断、调用 CLI；可执行文件和参数分开传递。未保存笔记的处理策略在插件设计时明确。
- 增加 CLI 版本兼容检查与真实状态展示；没有 CLI 时给出可操作说明，不能悄悄切换到另一套发布逻辑。
- RSS 可在渲染阶段就加入；邮件订阅要另行明确服务商、确认、退订及发送频率，再开发。移动发布另议。

**验收**：插件与终端对同一输入产物一致，失败信息可定位；改网站主题无需更新插件；关闭 Obsidian 后 CLI 仍可执行。
