# 开发计划

## 当前状态

已完成：目录骨架、根包清单、工作区范围、编辑器与 Git 规则、架构及协作文档。

尚未实现：任何业务模块、依赖锁文件、可运行命令、自动化测试、CI、云端部署及账号连接。当前没有可打开的博客。

## 下一步：最小发布链路

目标：关闭 Obsidian，也能用人工样例笔记导出内容、构建网站并检查结果。

1. 根据 Astro 和相关依赖的实际兼容性选择并固定 Node 版本，建立 web 与 CLI 的真实包清单、锁文件和检查命令。
2. 确定内容格式第一版，建立示例 Vault；覆盖中文路径、双链、图片、公开与未公开笔记。
3. 实现内容检查和导出；拒绝重复 ID、缺失附件及未经许可的嵌入。
4. 实现最小文章页、索引和 Pagefind 搜索，验证固定 ID 与 slug 分离。
5. 加入真实类型检查、内容测试及构建 CI。在部署目标确定后接 GitHub Pages。

验收：重复导出结果一致，未公开内容不出现在产物，文章和附件路径正确，失败有明确诊断；本地构建无需真实 Vault 或云凭据。

## 后续顺序

1. 发布工具：变更计划、提交内容、跟踪构建和部署；明确撤回与重试行为。
2. 评论：Worker/D1、本地开发、匿名提交、审核命令、公开字段隔离、权限和防刷验证。
3. Obsidian 薄插件：复用发布核心，展示变更计划与真实部署结果。
4. 订阅：RSS；确认邮件产品需求后再实现邮件订阅、退订与通知。
5. 完善视觉和交互、性能验证，以及有实际需求时的移动发布。

## 待确定事项

这些不阻碍目录初始化，在相应实现开始前确认。

| 事项 | 何时需要 |
| --- | --- |
| 真实 Vault 路径、常用插件语法、附件组织方式 | 接入真实内容之前 |

## 本次验证范围

初始化仅涉及文件和配置，无业务行为变更。检查 JSON、文档内部链接、工作区目录以及 Git 忽略规则；不宣称完成应用构建或端到端测试。
