# 架构

本文描述目标架构，尚非已实现能力。当前状态和开发顺序见 [开发计划](roadmap.md)，边界依据见 [最新 ADR](decisions/0002-external-input-build.md)。

## 三类位置

| 位置 | 内容 | 所有者 |
| --- | --- | --- |
| Corkoro 工具仓库 | CLI、发布核心、默认渲染器、插件、测试样例 | 开发者 |
| 用户内容与站点项目 | 原始 Markdown、附件、站点配置、页面与样式定制 | 用户 |
| 输出目录 | 公开内容包、静态站点及构建结果记录 | 构建工具 |

用户可以将 Vault 和站点项目放在不同目录。生产内容不要求进入工具仓库；仓库内的人工测试样例只是验证材料。源目录和输出目录不能相同或互为祖先；符号链接和 Windows junction 需按实际目标校验。

## 数据流

```text
Obsidian 插件 / agent / 终端
        ↓ 配置路径、显式参数
       CLI
        ↓
配置解析 → 源文件适配 → 构建规划 → 内容执行 → 公开内容包
                                                ↓
                                  默认 Astro 渲染器 + 外部站点定制
                                                ↓
                                            静态网站产物
                                                ↓ 显式 deploy
                                      GitHub Actions / GitHub Pages

访客 → 网站评论组件 → Worker API → D1
管理员 / agent → 管理命令或受控 API → 审核记录
```

规划阶段确定公开文章、附件、链接和输出之间的关系，执行阶段完成转换、写入和渲染。初期计划只存在于一次调用内；无需单独的调度平台或可执行计划文件。CLI 和未来插件使用同一套规则。

## 模块职责

- `tools/cli`：解析参数、读取外部配置、接入文件系统与构建工具、输出 JSON 或人类可读诊断。
- `packages/publisher`：配置归一化、筛选内容、解析引用、规划及执行转换；不导入 Obsidian API。源读取、产物写入和部署传输在适配边界接入。
- `packages/content-contract`：站点构建配置、公开内容包和诊断格式的版本与运行时校验。具体字段在首个里程碑冻结。
- `apps/web`：提供默认 Astro 渲染器，只读取公开内容包；外部站点配置和定制文件通过公开扩展接口接入，不能依赖原始 Vault。
- `apps/obsidian-plugin`：提供编辑器入口、构建状态与诊断展示；桌面调用 CLI 的可执行文件和参数数组，不拼接 shell 字符串，不内置另一套构建规则。
- `apps/api`：评论、审核和未来订阅业务的 Worker API，D1 为优先存储方向。
- `packages/api-contract`：分开定义公开返回与管理数据，避免公开数据库整行记录。

## 配置与路径

CLI 接受显式 `--config`。该参数本身相对调用者工作目录解析；配置内的相对路径及对应 CLI 路径覆盖参数统一相对配置文件目录解析。优先级为显式 CLI 参数、配置值、文档化默认值。必须用测试防止两种基准混淆。

配置描述内容根目录、语法格式、允许查找附件的目录、输出位置和站点设置。附件目录字段相对配置文件目录解析，同样需保持明确基准。语法格式可为普通 Markdown 或 Obsidian Markdown；解析实现独立于编辑器进程。先支持声明式 JSON，不提前支持任意脚本配置。

核心默认不修改源文件，不在源目录写缓存。写回文章 ID 若未来需要，必须单独设计命令。输出只写入指定范围，不能递归清理用户输入或任意既有目录；工具拥有的文件集合与旧产物清理策略在内容执行阶段实现。

## 内容包

公开内容包由 Markdown、附件和 manifest 组成；至少包含格式版本、稳定文章 ID、slug、文章路径及附件清单。文件路径相对内容包根目录，不向公开产物泄露本地绝对路径。

只导出显式 `publish: true` 的文章。附件目录只是查找范围，实际发布集合取自获准公开的文章引用。链接或嵌入不会自动公开其他笔记。重名目标、缺失附件、未经许可的嵌入和路径越界需给出明确诊断；未支持的扩展语法不能静默损坏内容。

输入文件名、标题和 slug 可变化，但文章 ID 保持稳定。改名、撤回及旧附件处理的验收见 [开发计划](roadmap.md)。

## 渲染、构建与部署

本地构建可以在关闭 Obsidian、没有云账号凭据时完成。网站默认布局来自工具，用户站点项目可以提供自己的样式和页面定制。最小切片先验证外部 CSS 定制，完整页面覆盖接口在渲染阶段明确。

构建只生成本地产物，不上传、不触发订阅邮件。部署消费特定构建结果，区分上传、远端执行和部署完成状态。CI 构建时使用显式提供的公开内容快照和可移植配置，不使用本机 Vault 绝对路径，也不上传整个私人 Vault。

是否由本地或 CI 完成最终渲染，在部署阶段明确；两种入口复用相同构建能力，不改变输入与输出协议。

## 评论与订阅

访客填写昵称、邮箱和正文，无账户及邮箱验证；服务端创建 `pending` 记录，管理操作批准或拒绝。公开查询仅返回已批准评论的公开字段，不含邮箱和内部审核信息。评论关联稳定文章 ID。

邮箱不作为身份或修改权限凭据，不自动加入订阅。RSS 可静态生成；邮件供应商、确认机制和频率未定，后续另行设计。将来发信以真实部署成功为依据并避免重复通知。

## 环境与管理

本地、预览和生产分开；管理命令显式选择目标。MCP / Wrangler 是管理员和 agent 的工具，不提供给访客。密钥不放入公开配置、内容包、CLI 日志或生成站点。
