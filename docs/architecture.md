# 架构

本文是目标架构，当前没有运行时代码。权威输入与命令见 [发布范围协议](publication.md)、[CLI 契约](cli.md)。最新边界由 [单配置与纯生成站点 ADR](decisions/0004-vault-config-generated-site.md) 确定。

## 三类位置

| 位置 | 内容 | 维护者 |
| --- | --- | --- |
| 用户 Vault | 原始文章、关于页、头像；一个配置文件内的发布清单、个人资料、友链、主题引用与设置 | 用户 / 插件 / 明确配置编辑命令 |
| Corkoro 工具仓库 | 发布核心、CLI、内置默认主题及渲染器、插件、人工测试数据 | 工具开发者 |
| Vault 外的输出目录 | 公开内容包、生成的 Astro 站点项目、静态网站与构建记录 | 生成器 |

用户不维护额外的站点源码项目。删除输出目录后，仅凭 Vault 输入、配置及固定版本的 Corkoro 可以重建；输出中不得存放唯一一份文章 ID、资料或主题设置。

## 数据流

```text
Obsidian / agent / 终端
       ↓ --config Vault/网站/corkoro.config.json
配置（含 publication.entries、site、theme）
       ↓ 显式文件引用
文章 + 关于页 + 头像等资源
       ↓ 解析、选择、依赖规划、校验
公开内容包（文章、站点页、公开资料和被引用资源）
       ↓ Corkoro 内置默认主题
生成的 Astro 站点项目 → 静态网站 → 显式 deploy

访客 → 评论组件 → Worker API → D1
管理员 / agent → 管理命令 → 审核记录
```

配置是唯一入口，不等于把 Markdown 长文或图片二进制塞进 JSON。发布清单、资料、友链和设置内联；关于页和头像仍是 Vault 中的独立文件，通过配置引用。工具读取普通文件，不依赖 Obsidian 进程。

## 模块职责

- `tools/cli`：读取显式配置并调用核心；init 创建配置，content 操作只编辑其中的 publication.entries。
- `packages/publisher`：扫描线索、解析统一配置、确定文章和页面入口、分析资源、规划与执行生成。读取和写出使用适配边界，不导入 Obsidian API。
- `packages/content-contract`：统一配置（含清单、资料和主题设置）、公开内容包及诊断的类型与运行时校验。
- `apps/web`：提供内置默认主题与站点生成/渲染能力，读取已筛选的内容包，不读取私人 Vault。用户不修改这里的源码或生成站点的文件。
- `apps/obsidian-plugin`：编辑 Vault 内配置、选择文章、调用同一 CLI、展示结果；不复制构建规则。
- `apps/api`、`packages/api-contract`：动态业务及公开/管理数据边界，匿名评论审核约定不变。

## 路径与写入边界

配置可以位于 Vault 内，推荐 `网站/corkoro.config.json`，无需放进 `.obsidian`。配置字段的文件路径相对配置文件目录；文章 entry.source 相对 source.root；Markdown 正文的相对资源路径按正文文件目录解析。

输出必须在 Vault、附件根目录及配置文件之外，不能覆盖输入。配置文件本身及其完整内容不能进入公开资源包。关于页源文件只因 site.pages 显式声明而进入对应页面，不会自动成为文章。

inspect/check/plan/build 对所有输入只读；init 明确创建配置，content 明确编辑配置的发布清单区块。这两类写入不允许修改文章、关于页和资源，也不能丢失同一配置中的个人资料和主题设置。并发修改必须检测冲突。

## 公开范围与主题

文章按 publication.entries 中 publish true 选择；站点页按 site.pages 中 publish true 选择；配置中填写的 profile 和 friends 是明确提供给网站展示的资料。两类页面的依赖都不自动公开其他笔记。文章列表和 RSS 默认只含文章，不包含关于页。

单配置的 site 与 theme 字段也要经运行时校验。文章和页面的 ID/路由需检查冲突；配置内只提取允许的公开资料，不拷贝整份 JSON。没有文章但有站点页、个人资料或友链时可以构建，完全没有内容时不回退全库构建。

首版只有 Corkoro 自带的 default 主题，通过配置设置配色模式和强调色。主题版本跟随工具版本。第三方主题、外部 CSS、布局覆盖和用户组件接口暂不实现，未来若需要再设计。

## 构建与部署

build 只写指定输出，可生成内容包、Astro 项目和静态网站；任何手工修改产物都会在下次重建丢失。部署是另一项显式操作，区分上传、构建和真实部署完成。

CI 使用经过筛选的公开快照与可移植构建配置，不上传整个 Vault。原始配置可能包含未启用条目和本地路径，因此也不能原样上传为公开站点配置。

## 评论与订阅

匿名评论填写资料后进入 pending，管理员审核后公开。公开接口不含邮箱和内部审核字段；未验证邮箱不授予修改权限，也不自动订阅。RSS 可静态生成；邮件订阅后续单独设计。MCP / Wrangler 仅供管理员和 agent 使用。
