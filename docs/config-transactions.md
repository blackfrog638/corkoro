# 配置写入事务协议

日期：2026-11-12。适用 init、content add/remove；只读命令不用写锁。定义可观察行为，不承诺当前 Node 标准库已提供所有所需原语。首次实现必须验证目标平台，否则返回 TRANSACTION_UNSUPPORTED；不可降级为不安全覆盖。

## 锁对象与范围

锁定的是配置的规范路径槽位：规范父目录身份 + 按该文件系统大小写规则规范化的文件名，不能锁被原子替换的配置 inode。多个路径别名若不能归并为同一槽位就拒绝写入；配置目标本身为符号链接或多硬链接文件时拒绝写入。尚不存在配置时也按同一槽位取锁，避免并发 init。

锁载体位于配置父目录的 .corkoro-state 下，名称由槽位键的 SHA-256 派生。目录归工具事务元数据；所有扫描和公开入口排除任何 .corkoro-state 目录。载体采用 OS 提供的进程生命周期互斥锁：进程退出后释放互斥，文件本身不是锁状态。适配器必须能验证这些语义，首版不承诺网络文件系统支持。

获取只尝试一次：占用返回 CONFIG_BUSY（4），不等待，无 --lock-timeout、--force 或自动重试。不存在“等待超时”的状态；IO 系统调用卡住仍属于平台取消/终止能力，不能承诺整个进程严格耗时上界。首版客户端自行决定何时重新调用。

不按 PID、文件时间或锁文件年龄强行解锁。正常释放不删除锁载体，避免另一个进程锁到新建的同名文件。遗留载体不阻止新进程取得空闲 OS 锁。元数据目录含固定 marker.json，内容恰为 {"format":"corkoro-transactions","version":1}；新目录由工具创建并独占创建该标记，既有目录缺失标记时不自动认领。载体是保持为空的普通文件，以槽位摘要加 .lock 命名，不以其内容记录持锁状态；临时文件用随机 UUID 加 .tmp 命名。载体/目录若是链接、身份不明、格式/版本非法则 UNSAFE_TRANSACTION_STATE，不覆盖或自动删除。

## 状态及事件

阶段为 Locate → Locked → Read → Prepared → Committing → Committed → Done。只读或无变化请求不进入 Prepared。失败可以进入 Done，进程终止进入 NoResponse。每个表格单元都指定结果；同一阶段同时发生事件时，以已经观察到的事件为准，提交点归适配器的线性化点。

| 阶段 | 正常进展 | 用户取消 | 可处理失败 | 强杀/进程退出 |
| --- | --- | --- | --- | --- |
| Locate | 安全定位并尝试锁 | 130/none | 不支持、占用、IO 等；none | 无响应；配置未写 |
| Locked / Read | 读取版本、构造并校验候选 | 130/none | 对应错误；none | 无响应；配置未写；OS 释放锁 |
| Prepared | 临时文件完成并复核原配置后进入提交 | 130/none，清理本次临时文件 | CONFIG_CHANGED 或 IO_ERROR；none | 无响应；配置未写；临时文件可残留 |
| Committing | 适配器返回确定未提交、确定已提交或未知 | 记取消请求，先等待提交结果，不回滚 | 依适配器结果分类，不能一律认作未提交 | 无响应；配置是旧或新完整版本 |
| Committed | 清理并输出结果 | 0/committed，附 CANCEL_AFTER_COMMIT | 清理失败只 warning；其它内部故障可 1/committed | 无响应；配置已提交 |
| Done / NoResponse | 终态，不再处理业务事件 | 不再次修改配置 | 不再次修改配置 | 不再次修改配置 |

Committing 的结果必须区分：

- 已知未提交：IO_ERROR/4/none；若有待处理取消则 CANCELLED/130/none。
- 已知已提交：进入 Committed；取消不撤销提交，结果为成功附告警。
- 无法确认：COMMIT_UNKNOWN/5/unknown，data=null、configVersion=null；有取消也不能谎报 130/none。停止写入，释放锁，由调用方读取当前配置确认。

参数/内容校验失败始终发生在提交前。无变化 add/remove 在锁内验证后直接返回 changed=false/effect=none，不重写格式。若取消在结果决定前被观察到，返回 130；结果已决定后不再改变结果。

## 提交与临时数据

1. 持锁读取完整配置；init 在锁内确认目标仍不存在。检查目标及父目录身份。
2. 构造候选、校验 W 与操作守卫。正文和资源从不写入。
3. 以随机独占文件名在同一文件系统的 .corkoro-state 中写候选并完成平台所需同步；临时内容可能含个人资料，不可进入输出或公开仓库。
4. 复核原配置内容版本与身份；init 仍须不存在。发现变化返回 CONFIG_CHANGED/CONFIG_EXISTS，不合并、不重试。
5. 更新用原子替换；init 用原子“仅当不存在才创建”。禁止“先删除旧配置再移动临时文件”。适配器需在进程崩溃模型下保证旧或新完整内容，无法支持时拒绝。断电耐久性不在首版证明中。
6. 标记提交结果，清理仅本次创建且身份未变的临时文件；释放 OS 锁。清理失败保留原提交结论并报告 CLEANUP_PENDING。

父目录可由 init 创建，失败后允许保留空目录；不能删除后来被他人使用的目录。即使 init 的同一目录下有其它用户文件，也不获得删除它们的权限。

## 恢复和重试

下次运行可继续使用有效锁载体，但不自动重放或提升旧临时文件为配置，也不按文件名猜测拥有权。旧临时文件保留并给 CLEANUP_PENDING；普通命令不自动清理之前进程的文件。需要清理时先停止相关写入进程，人工确认范围；不新增一个未经设计的 repair 命令。元数据不安全则直接失败，人工恢复后再执行。

没有响应/COMMIT_UNKNOWN 时重新读配置：add/remove 若目标已达到请求状态即可接受当前结果，否则在确认输入后重新提交相同请求；不能由“当前已达到”推断一定是某次请求完成，也不宣称恰好一次执行。init 重试 CONFIG_EXISTS 时核对配置，不覆盖。手工编辑器/同步软件仍不得与写命令同时写配置；事务方案只序列化合作的 Corkoro 写入者。

不保留事务状态作为用户唯一内容来源。关于页、资料、ID 等仍在原始文件和单一配置中；丢弃工具临时文件不应丢失已提交配置。
