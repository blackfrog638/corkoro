# 0009：公开内容包 v1 与单文件提交

- 状态：已实施库入口，2026-11-12
- 范围：第二阶段内容执行；不包含完整 build CLI 或站点渲染
- 前置：[引用规划](0008-readonly-reference-planning.md)、[配置事务](../config-transactions.md)

## 决策

输出固定为 `output.directory/content.bundle.json`，一个可移植的、自包含 JSON 文件。manifest、规范化文档树和资源字节在同一个文件内提交；输入配置不充当输出 manifest。具体字段见 [内容包协议](../content-bundle.md)。

首版采用单文件，是为了让现有经过验证的文件事务覆盖整个公开内容集合。更新时原子替换整个包，撤回文章及无用资源随之移除，不需要先删除旧目录，也不会误删用户放在输出目录的其它文件。无需增加代际目录、活动指针和回收协议。代价是图片使用 base64，体积约增加三分之一，生成及校验均在内存完成；首版不承诺适合大型媒体库或提供流式构建。

正文输出为受限、版本化内容树，链接使用稳定文档 ID、资源 ID 或外部 URL。双链别名转为文字标签，保留 CommonMark 结构；元数据、原始路径、语法树位置和未选条目不进入包。不预先输出 HTML，不把正文当代码。渲染器以后按节点类型生成并转义 HTML，统一解析路由和部署 base，不再读取 Vault。

资源 ID 是字节 SHA-256 加白名单扩展名；相同字节和扩展名去重。文档身份来自配置，内容摘要与身份分开；改源路径不会重分配 ID。构建摘要由规范字段顺序的 JSON 生成，无时间戳。摘要用于完整性和幂等比较，不是数字签名，也不能证明作者授权。

## 执行与提交

库入口重新加载配置，检查输入输出隔离，绑定输出真实路径，获取该目标的排他锁，再运行引用分析。转换只消费分析阶段捕获、校验过的同一批字节；不接受磁盘上的旧 plan，也不重读正在编辑的正文。它不是多文件同一时刻的快照：编辑发生在文件捕获之后，仅影响下次构建。

已有目标必须能通过格式、摘要、引用闭合及资源内容检查，否则返回 OUTPUT_NOT_OWNED 并保留原文件。有效内容包是该槽位的格式所有权标识，不是认证凭据。工具仅替换这个文件，管理相邻 .corkoro-state 内的自有事务文件；无目录递归删除。尚未支持对手工破坏的目标自动修复，需使用新的输出位置或由用户明确处理。

使用已有 Windows 本地 NTFS 辅助进程、FileShare.None 载体与 File.Replace / File.Move；复核目标及父目录/事务目录身份。相同 buildId 不重写。锁忙立即 OUTPUT_BUSY；目标冲突 OUTPUT_CHANGED。提交前失败保留旧包；提交响应未知返回 effect=unknown、退出 5，先读取完整包确认再重试；遗留临时文件不重放，报告 CLEANUP_PENDING。effect 描述目标内容包，none 仍可能创建输出目录和事务元数据。

Windows 实测包括暂存后进程退出、提交后调用方未获响应、提交前取消、锁竞争、目标硬链接拒绝和输出 junction 捕获后替换。持锁父目录重命名在实测环境被 OS 拒绝。目录身份复核不等于对恶意本地进程任意时序攻击的证明；断电耐久性、其它平台和网络文件系统不在当前保证内。

## 后续边界

完整 build CLI 在第三阶段编排内容包与 Astro。当前 API 是库入口，CLI 的 build 仍返回不支持；plan.changes 仍为 null，不借此引入增量计划。以后站点多文件提交、静态资源释放、base、缓存和发布流程需另定协议，不把单文件事务保证扩大到整个网站。
