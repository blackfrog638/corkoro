# 0014：博客产物仓库与部署快照

日期：2026-11-15。

Corkoro 根据用户配置在本地生成静态网站。构建独立于 Git 仓库和托管服务。GitHub Pages 是可选的部署目标；使用该适配器时，调用方显式提供产物仓库和分支。网站域名和 base 属于具体博客的配置。

第四阶段先实现 captureDeployment(outputDirectory, signal?) 与本地 package:site 工具。只读当前已提交站点，读取并复核全部文件摘要，验证内容包与站点 buildId 一致。返回 JSON 快照，包含相对文件路径、摘要、base64 字节、base、buildId 和 deploymentId；不含本地路径、生成项目源码、旧版本或私人配置。

统一格式、运行时校验由 content-contract/deployment.ts 定义。拒绝越界路径、大小写重复、文件与目录冲突、非法 base64、摘要不一致及缺少首页。按路径排序后计算 deploymentId；即使内容 buildId 相同，主题或搜索文件不同也产生不同部署版本。摘要用于完整性校验，不构成发布授权或来源签名。

JSON 快照是工具内部的可移交格式，不是要直接作为网站上传的单个 JSON 文件。后续 GitHub 适配器须将其中 files 还原为仓库内静态文件，显式选择目标仓库/分支，并区分提交完成和 Pages 上线完成。仅上传快照文件清单，不能上传整个输出根或 Vault。

当前实现只捕获和校验，不修改远端或本地输入。内存及 base64 开销与站点大小成正比；首版用于博客。远端上传、重试、旧发布覆盖保护及 deploy/status CLI 尚未实现。已有博客仓库可能包含历史文章和自定义域名配置，覆盖这些文件需要明确授权。

2026-11-18：仓库比较以显式本地分支解析得到的提交为基线，随后只读该提交，不比较脏工作区。首次接入没有 Corkoro 所有权清单，快照以外文件一律列为保留；覆盖域名配置、点开头路径、非常规文件或文件/目录碰撞列为冲突。报告仅用于核对，不能当作后续写入授权。

本地提交阶段要求传入 compare:site 的两个标识。用单独的临时 Git 索引从基线树开始添加或替换快照字节，生成以该基线为父的提交，最后通过 update-ref 校验旧提交号并一次更新分支。失败可能留下不可达 Git 对象，分支更新才代表提交完成。现有工作区检出的分支不作为写入目标。相同文件集合不会新增提交。
