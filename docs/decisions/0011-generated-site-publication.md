# 0011：生成 Astro 项目与站点版本切换

日期：2026-11-13。实现范围是最小站点库入口；完整 build CLI、搜索与部署仍未实现。

## 渲染边界

`apps/web` 从公开内容包读取捕获数据，不读取原始配置、Vault 或旧 plan。正文节点由公共层转为经过转义的 HTML，default 主题提供最小布局。内容写入 JSON 数据文件，不拼接进 Astro/JavaScript 源码；`set:html` 仅消费公共渲染层生成的 HTML。包内原始 HTML 节点仍由内容契约拒绝。外部链接不下载，图片按已验证的资源字节释放。

默认生成首页及所有文章/站点页；为避免遗漏已提供内容，最小布局同时展示 profile、友链和页面导航。这是可运行的基础布局，不表示第三阶段主题体验和搜索验收已完成。站内路径先统一 NFC，再经 URL 编码连接；Astro 写出同样规范化的目录，避免组合重音字符导致链接与文件名不一致。中文路由由 Astro 写出对应目录；Windows 无法表示的文件名返回 SITE_ROUTE_UNSUPPORTED，不静默丢页。

Astro 固定 7.4.11，注册表 engines 为 Node >=22.23.4，与项目 Node 26.13.0 实测兼容。通过 Node 可执行文件与参数数组启动官方 CLI，固定工作目录，不拼 shell；遥测关闭。CLI 的 config 参数按项目根相对路径传入（本版本实现按 root 拼接）。[官方 CLI](https://docs.astro.build/en/reference/cli-reference/)与[程序化 API](https://docs.astro.build/en/reference/programmatic-reference/)说明了两种调用入口，后者仍标为实验性。

每个项目有自己的 package.json、astro.config.mjs、页面模板、公开 JSON 数据和资源。首次构建通过 node_modules/astro 的本地 junction 复用工具固定依赖，不运行网络安装。项目是本机可重建产物，不是自带完整依赖的可移植源代码发行包；部署只取已构建 site 目录。

## 单指针提交

输出根中的 site.current.json 是工具拥有的当前版本记录；除此之外不认领根目录的用户文件。每次调用独占创建随机 corkoro-site-UUID 目录，包含 project 与 site。即使输入相同也生成新目录，首版不做缓存。

流程：读取并校验包 → 尝试当前记录的 OS 锁 → 校验旧记录与站点文件摘要 → 创建新目录 → Astro 构建 → 枚举并验证新 site 文件 → 原子提交当前记录。记录包含格式版本、generation、内容包 buildId 和完整静态文件路径/摘要清单。readSite 读取当前记录并验证清单、文件类型和摘要，返回明确 siteDirectory；消费者必须使用该路径，不能直接服务整个输出根。

复用 Windows 本地 NTFS 文件事务切换记录。提交前失败、取消或暂存后进程退出不改变旧指针；未知提交返回 effect=unknown/退出 5，先 readSite 再重试。OS 锁忙立即 OUTPUT_BUSY。坏记录或已被手工修改的活动站点不自动覆盖，返回 OUTPUT_NOT_OWNED。文件清单拒绝符号链接及多硬链接文件，读取时检查完整性。

不递归删除任何目录：旧版本、失败目录和 .tmp 都保留，不自动回放。结果的 retainedDirectory 告知本次已分配的目录（成功时也保留）；none 仅指当前版本未提交，并不表示未创建文件。旧版本可能包含已经撤回的公开内容，所以输出根不能整体上传或公开。未来清理命令需独立设计，不以名称前缀推断删除授权。

这是合作写入者的进程中断模型，不保证断电持久性、不合作编辑器或恶意本地进程竞争安全。输出根与传入包必须隔离。库仅知道包的位置，不能推断其原始 Vault；未来 build CLI 必须继续执行配置级的全部输入输出隔离校验。此次不把网站与内容包的两个提交伪装成同一事务。

## 验证与后续

真实 Astro 构建覆盖外部临时目录、移走 Vault 后构建、中文 route、项目 base 和资源；故障测试覆盖锁竞争、Astro 报错、取消、暂存后进程退出、非法包、输出重叠、陌生记录与站点篡改。人工样例已在桌面和移动宽度检查。后续继续主题视觉、搜索、完整 CLI 编排及 CI。
