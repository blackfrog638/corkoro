# 0010：站点地址与主题职责

日期：2026-11-13。地址校验与内容包传递已实现；以下渲染规则是下一步的实现约束，尚无网站产物。

## 地址

Vault 配置增加可选 `site.address`，包含必须成对提供的 `origin` 和 `base`。例如：

```json
{ "origin": "https://blackfrog638.github.io", "base": "/corkoro/" }
```

origin 必须是规范 HTTP(S) origin，不含路径、尾斜线、查询、片段或凭据。不猜测 GitHub 账号、登录状态或部署目标。base 为 `/` 或以斜线开头结尾的非空 ASCII 路径段；段内允许字母、数字、下划线、连字符及非连续的内部点。拒绝百分号、点段、反斜线、重复斜线和空白；首版不接受中文部署前缀，文章中文 slug 不受影响。

不设置 address 的旧配置仍可扫描、选择和生成内容包，不填充虚假域名。后续本地渲染以 `/` 处理缺省地址，不生成 canonical 绝对链接；明确配置地址时，所有站内页面、导航、资源和搜索 URL 都需包含 base。部署阶段必须要求明确地址与目标，当前不实现部署。

address 原样进入公开内容包 manifest.site，使用同一运行时 schema，不改变文档 ID 或包内 route。更改地址会改变 buildId，文档正文摘要保持不变。配置和内容包仍为未发布 v1 的加法扩展；旧包由新读取器继续接受，新带字段的包不能交给旧严格读取器，调用方须使用匹配工具版本。

## 主题

公共层处理正文节点、链接和资源映射、HTML 转义及地址拼接；主题只负责视觉和布局，不重新选择公开内容。所有完整主题必须支持文章和普通站点页；关于页就是普通页面，不依赖文件名或固定 about ID。

默认主题展示全部启用页面的导航，profile 在首页展示，非空 friends 进入友链页；未配置内容不生成空栏目。后续主题可以改变位置和布局，但不可静默丢弃明确提供的内容；缺失模板需公共兜底或明确失败。搜索、评论、订阅是独立能力，不强迫主题启用动态服务。首版继续只允许 default，不引入主题包、用户代码或外部 CSS。

## 输出边界

内容包单文件事务只保证内容包本身，不代表多个网站文件整体原子提交。站点生成实现前必须另定暂存目录、所有权、成功切换和失败恢复协议，并经过故障测试；不能在活动输出上直接删旧写新。
