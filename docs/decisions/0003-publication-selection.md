# 先发现内容，再显式选择构建入口

日期：2026-11-11

状态：已接受。落实用户对陌生 Vault 接入流程与外部发布清单的确认。

后续调整：[单配置决策](0004-vault-config-generated-site.md) 将输入清单合并到 Vault 内配置的 publication.entries，不再维护独立 publication.json；显式选择与引用不扩大授权的原则继续有效。

## 问题

先前流程从 check 开始，假设用户已经知道发布哪些文章，也未明确公开标记必须写在笔记还是可以放在外部。只提供构建命令不能解决陌生 Vault 的接入与选择，且强制写源笔记与只读输入的方向不一致。

## 决策

1. 外部 `publication.json` 是当前站点的公开授权来源。只有 entry 的 `publish: true` 启用文章。笔记属性、标签和目录只能提供候选线索，不自动授予或覆盖清单授权。
2. 初始化默认空清单，零文章，不回退全库构建。扫描、初始化、选择、检查、计划、构建、预览、部署是不同职责。
3. 发布清单同时保存稳定 ID 和 slug，不要求修改原始笔记。选择命令只修改外部清单，停用保留身份；构建 manifest 是工具生成的另一种文档。
4. 引用图只决定依赖，不扩大文章授权范围。已选文章引用未选文章必须诊断；私人笔记不能作为普通附件绕过规则。
5. `inspect` 可在没有配置时运行，`init` 建立外部项目，`content` 管理选择；`plan` 解释包含理由及阻断引用。后续命令详参在对应阶段冻结。
6. 首版用逐文件选择；持续目录/标签匹配和批量导入以后再设计，不能把建议当成授权。

## 对现有决策的影响

细化前两份 ADR 的“显式公开标记”为外部清单 entry 的布尔属性。替代旧 roadmap 中要求在源笔记填写 ID 的默认方案；源笔记继续只读。配置、发布清单、构建产物分开，GN/Ninja 的规划与执行分工保持不变。

## 验证

使用人工陌生 Vault，包含没有任何发布属性的文章、带 `publish: true` 但未选择的笔记、被引用的未选笔记和无引用附件。验收新项目零选择、按清单精确构建、阻断未授权引用、原文不变和重复选择保留 ID。具体见 [发布范围协议](../publication.md) 与 [CLI 契约](../cli.md)。
