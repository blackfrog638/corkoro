# Vault 内单配置与纯生成站点

日期：2026-11-11

状态：已接受。本决策覆盖此前独立发布清单文件、配置必须在 Vault 外和用户维护站点源码的约定。协议尚未发布，无运行时代码需要迁移。

## 用户要求

用户不编辑站点项目，站点应完全生成。文章以及配置、发布清单、关于页、个人资料、友链、头像、主题引用和设置都保存在 Obsidian 中，由 CLI 引用。Corkoro 自带一个默认主题即可。

## 决策

1. 以 Vault 内一个 corkoro.config.json 为入口。publication.entries 内联文章清单；site 内联资料和友链，并引用独立的关于页 Markdown、头像等文件。图片和长文无需塞进 JSON。
2. 不再要求维护独立 publication.json 或外部站点源码目录。文章 ID、slug、个人资料和主题设置全部是持久输入，不能只存在于输出中。
3. 配置允许在源目录内，推荐 网站/。check/plan/build 对所有输入只读；init 和 content 是显式配置编辑操作，只能创建/修改指定配置，保留其它区块和正文文件。
4. 输出必须在 Vault 与资源根目录外。站点项目、内容包和静态网站均为可重建产物，用户不在生成文件里做定制。
5. Corkoro 提供 default 主题，首版只开放文档化主题设置。外部 CSS、布局覆盖、第三方主题和自定义组件接口移出当前实施范围。
6. 文章与独立页面分别显式选择。profile/friends 是显式展示数据；关于页不进入文章列表/RSS；零文章但有页面或个人资料的站点可以生成。初始化所有内容为空时仍不得发布整个 Vault。

## 后果与验收

content 修改的是包含多个区块的配置文件，必须保留个人内容和主题设置，并检测并发变更。配置本身不可作为资源公开。页面路由和文章路由必须统一检查冲突。

用 Vault 内配置、关于页和头像样例验证路径解析、默认主题设置和页面依赖。证明只读构建不改输入、显式选择操作只改配置，以及删除输出后可凭输入与固定版本工具重建。
