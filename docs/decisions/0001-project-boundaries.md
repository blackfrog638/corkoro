# 独立网站、发布工具与编辑器入口

日期：2026-11-11

状态：作为本次初始化的基线。服务商接入仍需真实账号和环境验证。

后续细化：[外部输入与构建边界](0002-external-input-build.md) 明确用户站点项目与工具仓库分离、桌面插件通过 CLI 使用核心，以及构建和部署的独立职责。涉及调用与目录约定时以该决策为准。

## 背景

用户需要从 Obsidian 发布到 GitHub Pages，前端高度定制、文章加载轻量，评论无需验证邮箱但必须经作者审核。开发、发布和日常管理应适合 agent 操作。

## 决策

1. Astro 负责内容网站；TypeScript 为主要实现语言。GitHub Actions 构建，GitHub Pages 托管静态产物。
2. 网站与 Obsidian 插件解耦；共享发布核心由插件和 CLI 调用。网站以版本化的公开内容包为输入。
3. 使用一个 pnpm 工作区维护模块，不提前建设通用插件系统或独立微服务体系。
4. Cloudflare Workers + D1 为动态业务的优先实现方向；MCP / Wrangler 用于开发和管理。当前不创建云端资源。
5. 评论匿名提交、审核后公开；去掉此前建议的访客账户系统和邮箱验证。管理员权限仍须保留。
6. Pagefind 为搜索方向；仅在需要交互时引入 React。样式体系和视觉方案稍后确定。
7. RSS、邮件订阅与评论分开；Resend 仅是候选，不视为已确定服务商。

## 代价

需要自行维护发布转换与评论业务。解耦引入内容格式和适配层，但避免网站绑定 Obsidian 运行环境。Workers + D1 减少服务器运维，仍存在平台配额和迁移工作。

## 重新评估条件

- 若目标转向完整复现 Obsidian 知识库且减少定制，可重新比较 Quartz。
- 若会员、复杂用户权限成为核心，可重新评估认证及数据库方案。
- 若目标读者网络实测不满足要求，可更换托管或 API 平台，保留内容格式和模块边界。
- 移动发布需求出现后再确定远端构建入口，不假定手机能运行桌面 CLI。
